Unsolicited concept · Franchise operations

The walk-in reads 44°F at 10:12 PM. What happens next?

A closing-shift manager logs a cooler temperature above the SOP limit. The assistant checks it against approved content, shows its source and how sure it is, and suggests next steps. The manager approves them. HQ sees the exception and who approved what, without having to ask.

        Design decisions

        Show the evidence before asking for a decision

        Evidence comes before the recommendation
        The reading, the limit and the SOP clause appear before any action. A tired manager at close should never approve something she can't check in a glance.
        Confidence is shown per claim, not as one score
        "Above the limit" is a direct comparison, so it's high. "Door left open during delivery" is a guess from past logs, so it's medium. A single score would hide which part to trust.
        Permissions shape the actions up front
        Opening a maintenance ticket needs the owner. The manager sees this before she taps and can send it to him, instead of hitting an error afterwards.
        Streaming shows progress right away
        The checks list starts within a few hundred milliseconds, so the wait reads as work being done, not a frozen screen.
        HQ gets the full trail, not just an alert
        The row changes state and the activity log records what the assistant suggested and who approved it. That builds on an activity log I designed for a multi-role HR platform.

        Open questions

        What I'd test before building this for real

        Signal inside the walk-in (prototyped)
        A walk-in cooler is an insulated metal box, so the phone may have no signal where the reading is taken. I added a first pass: turn the signal off on the phone and log a reading. It saves locally, HQ doesn't see it yet, and it sends when signal returns. Next I'd test whether managers notice the "not sent yet" state before leaving the walk-in.
        Who is allowed to decide on discarding food
        I kept discard decisions with the owner. Brands may set that differently, so the permission should come from each brand's roles, not be fixed in the design.
        Whether "Not now" should exist
        Skipping still logs the exception so HQ sees it. I'd check with ops leads whether a food-safety exception should ever be skippable.
        Limits per brand and per unit
        41°F is the common cold-holding limit in the US, but the value should come from each brand's approved SOP, which is what the source chip points to.
